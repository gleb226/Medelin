# Medelin

Офіційний репозиторій проєкту **Medelin**: брендова промо-сторінка кав’ярні (**MedelinSite**) + бекенд/Telegram‑бот (**MedelinBot**) + Nginx конфіг для продакшн‑запуску.

## Про продукт

**Medelin** — це набір компонентів для цифрової присутності кав’ярні:

- **Сайт**: сучасна бренд‑сторінка з акцентом на меню/каву/контакти, легка та швидка (статична видача).
- **Telegram‑бот**: прийом замовлень/діалоги/інтеграції з оплатою та доставкою (через токени провайдерів у змінних середовища).
- **Nginx**: один вхідний “фронт‑двері” для статики + проксі на `/api/`.

Проєкт розроблений так, щоб:

- виглядати як “дорогий” комерційний продукт (UI/UX, SEO‑мета, структура сторінок);
- бути готовим до продакшну (кешування статики, обмеження розміру запитів, базова hardening‑конфігурація);
- не зберігати чутливі дані в репозиторії (жодних реальних токенів/паролів у коді).

## Ключові можливості

### MedelinSite (Frontend)

- Брендова головна сторінка, меню, контакти, додаткові сторінки.
- Оптимізація під мобільні (responsive).
- SEO‑пакет: мета‑теги, OpenGraph/Twitter cards, `robots.txt`, `sitemap.xml`.
- Локальні JS‑модулі для UX: меню, навігація, інтерактив.
- Кеш‑файли (`MedelinSite/cache/*.json`) як легкий “контент‑шар” для меню/локацій/соцмереж.

Додатково (продуктовий рівень):

- **Єдина айдентика**: типографіка, кольори, компоненти, повторювані секції.
- **Висока швидкість**: статика + кешування ресурсів на edge.
- **Дружність до маркетингу**: сторінки/секції легко оновлюються (без “важкого” CMS), а `sitemap.xml` і мета‑теги дають базу для індексації.

### Контент та сторінки

Сайт влаштований як набір окремих сторінок/секцій, з фокусом на конверсію:

- “Головна” — перше враження, історія бренду, ключові CTA.
- “Меню” — структурована подача позицій (кава/десерти/інше).
- “Кава в зернах” — окремий продукт‑напрям (для продажу/замовлень).
- “Контакти” — локації, соціальні мережі, зворотній звʼязок.

### MedelinBot (Backend + інтеграції)

- Центральна бізнес‑логіка для бота/замовлень.
- Підключення до БД через конфіг (підтримка `mongodb://...` і `mongodb+srv://...`).
- Інтеграції оплат/провайдерів (працюють **лише** при наявності токенів у змінних середовища).
- Адмін‑утиліти/обробники для керування (в межах можливостей бота).

### Nginx (Edge)

- Статична видача сайту з кешуванням для assets.
- Проксі на `/api/` до бекенду.
- Базова security‑hardening конфігурація (див. розділ “Безпека”).

## Структура репозиторію

- `MedelinSite/` — фронтенд (HTML/CSS/JS, SEO файли, кеш‑дані).
- `MedelinBot/` — бот/бекенд (Python).
- `nginx.conf` — продакшн‑конфіг Nginx (статика + `/api/` + security headers).
- `docker-compose.yml`, `Dockerfile`, `start.sh` — інфраструктурні файли (контейнери/запуск).
- `.gitignore` — правила ігнорування локальних файлів (у т.ч. `.env*`).

## Архітектура та потоки даних

На рівні “високо‑рівневої” картини:

```text
Browser
  |
  |  (static HTML/CSS/JS)
  v
Nginx  ----->  /api/  ----->  MedelinBot backend  ----->  DB / інтеграції
  |
  +-- /uploads/ (тільки статичні файли з whitelist‑поведінкою)
```

- **Сайт** віддається як статика (швидко, дешево, надійно).
- **API** ізольований шляхом маршруту `/api/` і обмежений по методах.
- **Інтеграції** (оплата/доставка) активуються тільки при наявності відповідних змінних середовища.

## Принципи дизайну (UI/UX)

Проєкт зібраний з думкою про реальний бізнес‑сайт:

- **Перший екран**: чіткий оффер + швидкий шлях до меню/контактів.
- **Сканованість**: короткі блоки, списки, видимі заголовки.
- **Довіра**: соцмережі, контактні дані, зрозуміла структура.
- **Mobile‑first**: меню та навігація працюють так само добре на телефоні, як і на десктопі.

## Продуктивність

Стратегія продуктивності базується на простих, але ефективних речах:

- статичні сторінки (мінімум runtime‑логіки);
- кешування важких assets через Nginx (`expires` + `Cache-Control`);
- обмежений набір зовнішніх ресурсів (шрифти/іконки).

## Безпека та приватність

Цей репозиторій орієнтований на продакшн‑практики “без зайвого ризику”:

### 1) Нуль секретів у коді

- `MedelinBot/app/common/config.py` **не містить** реальних токенів/паролів у дефолтах.
- `.env` файли не комітяться: вони ігноруються через `.gitignore` (патерни `.env` і `.env.*`).
- Для Docker використовуйте шаблон: `MedelinBot/.env.docker.example`.

### 2) Nginx hardening

У `nginx.conf` увімкнені базові захисні заголовки та політики:

- `Content-Security-Policy` (CSP) — обмежує джерела скриптів/стилів/шрифтів/зображень.
- `X-Content-Type-Options: nosniff` — зменшує ризики MIME‑sniffing.
- `X-Frame-Options: DENY` + `frame-ancestors 'none'` — захист від clickjacking.
- `Referrer-Policy` — менше витоків URL‑параметрів.
- Блокування доступу до “прихованих” файлів (`/.git`, `/.env`, backups і т.п.).
- Для `/api/` — `limit_except` (дозволені тільки `GET/POST/OPTIONS`).

### 3) Практичні рекомендації (важливо)

Якщо реальні ключі/токени колись потрапляли в GitHub (навіть якщо зараз їх вже нема в актуальному коді) — вважайте їх скомпрометованими:

- **ротуйте** токени/паролі у всіх провайдерах;
- перевірте журнали доступу;
- увімкніть 2FA та мінімальні права доступу.

## Якість та підтримуваність

- Frontend має виділені стилі/компоненти (`MedelinSite/css`, `MedelinSite/js`).
- У репозиторії є конфіги форматування/лінтингу для фронтенду (`MedelinSite/.prettierrc.json`, `eslint.config.js`, `stylelint.config.cjs`).
- Конфіг/ключі для інтеграцій винесені в змінні середовища (щоб код був безпечний для публікації).

## Roadmap

- Повна ізоляція бекенду в окремий сервіс + healthcheck/metrics.
- Тонше налаштування CSP (hash/nonce для стилів/без `unsafe-inline`).
- Rate‑limit для `/api/` (через `limit_req_zone` в `http{}` контексті або зовнішній балансер).
- Автоматичні security‑скани (gitleaks/semgrep) у CI.
- A/B‑покращення конверсії на сайті (CTA, швидкість, micro‑animations).
